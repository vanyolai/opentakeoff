# Interface languages

OpenTakeoff's web interface supports English and Hungarian. English is the
canonical fallback catalog; Hungarian is the first additional language.

## Runtime behavior

- The language picker is available on the project screen and in both workspace
  layouts.
- The selected language is stored under `opentakeoff.language` and survives a
  reload.
- A new browser chooses the first supported value in this order: saved choice,
  `VITE_DEFAULT_LANGUAGE`, browser language, English.
- The active language also updates the document's `lang` attribute, title,
  number formatting and date formatting.
- Language and display units are independent preferences. Selecting Hungarian
  does not switch a project to metric, and switching units does not change the
  interface language.

Self-hosted deployments that should open in Hungarian by default can build with:

```sh
VITE_DEFAULT_LANGUAGE=hu npm run build
```

Users can still override that default with the language picker.

## Developer contract

The catalogs live in `web/src/i18n/locales/en.js` and `hu.js`. Persisted project
fields, protocol keys, command ids and stable machine-readable export schemas
are not translated. User-visible React text should use `useTranslation`; code
outside React can import the initialized instance and locale helpers from
`web/src/i18n/index.js`.

Every English leaf key must exist in every other catalog. The parity test in
`web/test/i18n.test.ts` rejects missing or extra keys. Add the English string
and all translations in the same change.

CSV/XLSX field names remain stable for machine compatibility in this first
slice. The on-screen/printed report is localized. The Marked Set PDF remains an
explicit follow-up because its current standard PDF font cannot encode all
Hungarian double-acute characters (`ő`, `ű`); it must move to an embedded
Unicode font before translated cover text is safe.
